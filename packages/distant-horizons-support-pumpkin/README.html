DistantHorizonsSupportPumpkin ​v0.1.1

This unofficial integration lets Java players use Distant Horizons with terrain from your Pumpkin server.

See the plugin guide and API reference on the documentation site.

Installation ​

Download distant-horizons-support-pumpkin.wasm from the plugin's GitHub release, put it in your server's plugins/ folder, and restart Pumpkin. On the first load, a full restart lets Pumpkin ask for the plugin's permissions; hot reload cannot prompt for them.

Permissions ​

Pumpkin asks you to approve these on the server console when it loads the plugin. It skips the question when the [plugins] table in pumpkin.toml lists all of them in allowed_permissions or sets ask_permission_confirmation = false. Pumpkin remembers your answer and asks again after the plugin file or this list changes.

PermissionWhy
fs.read.dataRead settings and cached LOD terrain.
fs.write.dataWrite settings and persist captured LOD terrain.
http.outboundCheck Pumpkin Market for plugin updates.

Compatibility and terrain ​

Targets Distant Horizons 3.3.4, using network protocol 16 on Java Edition. Bedrock players do not open DH sessions. Install the Distant Horizons client mod separately. A client using another DH protocol is disconnected with an incompatibility message. DH sessions open only in worlds whose names are at most 150 characters of ASCII letters, digits, _ and -, optionally split by one : as in minecraft:overworld. In other worlds the plugin logs a warning and the client gets no LODs. The protocol format follows Distant Horizons core 3.3.4.

The plugin builds LOD sections of 64 × 64 blocks, which covers 16 server chunks. It captures a section only while all 16 chunks are loaded, and it cannot load or generate distant chunks. A request for unloaded terrain stays pending and retries with exponential backoff until the chunks load or the client cancels it. Loaded terrain that contains only air is valid and gets cached. By default, each column uses its surface biome. Set sample_biomes_3d = true under [worlds."<world>"] to sample cave and other vertical biomes. This adds one biome lookup for each sampled block. Blocks placed or broken by players, crop growth and fire spread invalidate the affected cached sections. Other world changes can stay cached until the next refresh when the pinned Pumpkin API does not report their exact world and position. A section holds at most 131072 material segments, and a transfer packet carries at most 30000 data bytes. When a client sets a bandwidth limit, the plugin sizes each fragment, including its 13-byte protocol envelope, to fit in 20 seconds of credit. The credit bucket holds at most one full 30013-byte fragment message.

How it works ​

The plugin answers Distant Horizons requests from terrain that Pumpkin has loaded. It captures materials, caves, biomes and lighting, then stores each section in a memory cache and a disk cache with separate limits. Disk entries survive restarts, and cached sections are still sent after their chunks unload. Because the plugin can't load or generate chunks, an area gets LODs once players or a chunk-loading tool have brought it into range.
