DynamicLightsPumpkin ​v0.1.0

DynamicLightsPumpkin shows temporary light around supported items and nearby entities without changing the world.

See the plugin guide and API reference on the documentation site.

Installation ​

Download dynamic-lights-pumpkin.wasm from the plugin's GitHub release, put it in your server's plugins/ folder, and restart Pumpkin. On the first load, a full restart lets Pumpkin ask for the plugin's permissions; hot reload cannot prompt for them.

How it works ​

Holding a supported light source shows a temporary invisible light block only to your client. It updates when you enter another block, change held slot or inventory, drop or use an item, teleport, respawn, or change world. Event updates read the completed action on the next tick. Movement within the same block is ignored to avoid repeated world and inventory lookups. Either hand can provide light, and the brighter configured item wins. The server world is never changed, so no light block can replace terrain or be left behind after a crash.

Built-in sources, including torches and lava buckets, are listed in config.toml. Remove an entry to disable it, change its light_level, or add any item ID you want to support.

Entity lights are enabled by default. The plugin checks entities in a 15-block cube around each player every 10 ticks by default and sends changes only when a configured entity light moves, changes level or leaves range. Configure entity_sources with Pumpkin entity names such as blaze, magma-cube, glow-squid or glow-item-frame. Dropped items use the same configured level as their held form when the plugin observes them spawn or drop. A player drop is identified only when exactly one new nearby item entity appears; ambiguous drops and existing drops after a plugin or server restart are deliberately not guessed at.

Use /dynamiclights to toggle dynamic lights for yourself. It is available to all players by default and remembers your choice. Overlapping sources use the brightest level, and disabling lights or unloading the plugin restores the real blocks.

The plugin retains its old recovery data reader solely to repair temporary server light levels written by an earlier version.

Permissions ​

Pumpkin asks you to approve these on the server console when it loads the plugin. It skips the question when the [plugins] table in pumpkin.toml lists all of them in allowed_permissions or sets ask_permission_confirmation = false. Pumpkin remembers your answer and asks again after the plugin file or this list changes.

PermissionWhy
fs.read.dataRead its light-source settings, player preferences and old recovery data.
fs.write.dataWrite its light-source settings and player preferences, and clean up old recovery data.
http.outboundCheck Pumpkin Market for plugin updates.

Configuration ​

Settings live in plugins/data/DynamicLightsPumpkin/config.toml. The plugin creates the file if needed, adds settings from the schema and removes settings no longer defined there. Values for existing settings are preserved.

OptionTypeDefaultDescription
sources."<item>".light_levelintegernoneLight emitted while this item is held, from 0 through 15.
entities.enabledbooleantrueWhether configured entities emit temporary client-only light.
entities.refresh_interval_ticksinteger10Ticks between nearby-entity refreshes. Higher values reduce work but make moving lights less smooth.
entity_sources."<entity type>".light_levelintegernoneLight emitted by this entity type, from 0 through 15.
A fresh install gets this file:

# This file is managed by the plugin: when it starts, settings that were added are written here with
