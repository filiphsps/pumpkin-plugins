Publish to Pumpkin Market ​v0.0.7

Add this action after your workflow has built the plugin's .wasm file. It uploads that file to an existing Pumpkin Market listing; it won't build the plugin or create a listing for you. GitHub runs the action on Node 24, so you don't need actions/setup-node just for this step.

See the action guide and API reference on the documentation site.

yaml
steps:
  - uses: filiphsps/pumpkin-plugins/actions/publish-to-pumpkin-market@publish-to-pumpkin-market-v0.0.7
    with:
      plugin-name: MyPlugin
      version: 1.2.3
      wasm-file: dist/my-plugin.wasm
      api-token: ${{ secrets.MARKET_API_TOKEN }}
      release-notes: |
        ## Changes
        - Fix plugin behavior

The example selects a listing by name. Name lookups search up to 20 Market results for a case-insensitive exact match. If your workflow already has the listing's numeric database ID or public ID, use plugin-id for a direct lookup instead. Set exactly one of plugin-name and plugin-id.

The tag in the example is this action's Release Please tag. Action releases are independent of your plugin's version and of other action releases; Release Please updates the example tag when this action gets a new release. In this repository's own release workflows, the action is called from ./actions/publish-to-pumpkin-market.

Inputs ​

InputRequiredDefaultDescription
plugin-nameNoExact listing name; set this or plugin-id, but not both
plugin-idNoNumeric database ID or public ID; set this or plugin-name, but not both
versionYesPlugin version to publish, without a leading v
wasm-fileYesPath to the plugin .wasm file
api-tokenNoMarket API token with plugins:update and plugins:versions:upload scopes; required unless warn is true
api-urlNohttps://market.pumpkinmc.orgPumpkin Market base URL
trackNostableRelease track
release-notesNo""Release notes to include in Market version metadata
warnNofalseWarn instead of failing when credentials or the Market listing are unavailable

Outputs ​

OutputDescription
listing-idResolved numeric Market database ID
listing-nameCanonical Market listing name
statusOperation result (success or skipped)
published-versionVersion successfully published to the listing

Give api-token a GitHub secret with the plugins:update and plugins:versions:upload scopes. By default, an empty token or a missing or unpublished listing fails the step. Set warn: true when you want those cases to produce a warning and skip the upload instead. Lookup and upload errors still fail the action. When GitHub provides a step summary, the action adds a result for both successful uploads and skipped uploads.
