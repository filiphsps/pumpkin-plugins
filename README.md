This monorepo brings together plugins for [Pumpkin](https://github.com/Pumpkin-MC/Pumpkin),
the tools used to build and release them, reusable GitHub Actions, and VS Code extensions. Most
components are written in TypeScript. It was originally built on and inspired by
[pumpkin-api-ts](https://github.com/Pumpkin-MC/pumpkin-api-ts).

## Getting started

Use the Node.js version pinned in [`.node-version`](.node-version) and the pnpm version in
[`package.json`](package.json). From the repository root, install dependencies, build the plugins,
and run the unit-test suite:

```sh
pnpm install
pnpm build
pnpm test
```

## Creating a plugin

Run the generator to scaffold a plugin in `packages/`:

```sh
pnpm gen
```

It asks for a folder name, a plugin name, and a description, then registers the package for releases
and generates its README. To provide those answers without prompts, pass them in order:

```sh
pnpm gen --args my-plugin MyPlugin "Does a thing"
```

See [Creating a plugin](docs/creating-a-plugin.md) for the generated files and next steps.

## Creating an action or extension

Run `pnpm gen:action` to scaffold a GitHub Action, or `pnpm gen:extension` to create a VS Code
extension. Their guides explain what each generator creates and how releases work: [Creating an
action](docs/creating-an-action.md) and [Creating an extension](docs/creating-an-extension.md).

## Command reference

Run these commands from the repository root. Most workspace tasks use [Turborepo](https://turborepo.dev),
which reuses cached results for packages that haven't changed.

| Command | What it does |
| --- | --- |
| `pnpm gen` | Scaffold a new plugin; see [Creating a plugin](docs/creating-a-plugin.md). |
| `pnpm gen:action` | Scaffold a GitHub Action; see [Creating an action](docs/creating-an-action.md). |
| `pnpm gen:extension` | Scaffold a VS Code extension; see [Creating an extension](docs/creating-an-extension.md). |
| `pnpm build` | Build every plugin to `packages/*/build/*.wasm`. |
| `pnpm lint` | Run Biome's lint, formatting and import-order checks, followed by the JSDoc check. Use `pnpm lint:fix` to apply fixes. |
| `pnpm lint:commits` | Check the latest commit message against the Conventional Commits rules used by CI. |
| `pnpm typecheck` | Typecheck every package in the workspace. |
| `pnpm test` | Run the workspace unit tests. |
| `pnpm coverage` | Run unit tests with V8 coverage; LCOV reports go under package and action coverage directories. |
| `pnpm test:scripts` | Run the tests for repository checks, release scripts and agent hooks. |
| `pnpm test:integration` | Build the plugins, then run their tests against a real Pumpkin server. Set `PUMPKIN_BIN` to choose the server binary; see [Testing](docs/testing.md). |
| `pnpm readme` | Regenerate component READMEs, catalogs and documentation references. |
| `pnpm check` | Check release configuration, package metadata and docs against the repository; see [Code style](docs/code-style.md). |
| `pnpm fix` | Check release configuration, repair package metadata, regenerate READMEs and documentation links, then apply lint fixes. |
| `pnpm dev:docs` | Generate API references and serve the documentation site locally. |
| `pnpm docs` | Generate API references and build the full static documentation site. |
| `pnpm docs:api` | Generate type declarations and API reference pages for the documentation site. |
| `pnpm docs:site` | Build the VitePress site from the generated API pages. |
| `pnpm docs:preview` | Preview the most recently built documentation site. |
| `pnpm package` | Collect built plugins in `dist/<plugin>.wasm` and create checksums. The reusable action handles signing separately; see [CI and releases](docs/ci-and-releases.md). |

## GitHub Actions

Reusable actions live in `actions/{name}/`, with their own metadata, implementation and README.
Release Please versions and tags each action independently, so releasing one action doesn't also
ship plugin builds or other actions.
