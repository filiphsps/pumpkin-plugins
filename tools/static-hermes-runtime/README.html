Static Hermes Runtime ​

This package supplies the Static Hermes backend for Pumpkin plugin components. It compiles bundled JavaScript to Hermes bytecode with hermesc, then links the bytecode, Hermes, the JSI shim, and generated Pumpkin/WASI bindings into a WebAssembly component. Static Hermes is the default engine; QuickJS remains available as an alternative.

Start with the runtime documentation. It links to the benchmarking guide; this README covers toolchain setup, build profiles, compiler and linker flags, and API coverage.

Prepare the toolchain ​

Requirements: Git, CMake, and Ninja. Rust/Cargo is needed only if the configured wit-bindgen version is not already installed.

sh
pnpm --filter @pumpkin-plugins/static-hermes-runtime prepare-hermes

Preparation uses the SDK release configured in wasi-sdk.json, verifies its published checksum, installs the configured wit-bindgen version if needed, and caches the toolchain under .cache/hermes/ by default. It checks out the source commit in hermes-source.json, applies the ordered patches in hermes-patches/, then builds host hermesc and the full and lean WASI 2 Hermes/JSI libraries.

The cache is reused while its source pin, patches, toolchain, and build settings match. A changed input triggers a rebuild. Preparation refreshes the managed checkout when the source pin changes and rejects local Hermes source changes outside the managed patch set. Concurrent builds share a preparation lock.

Plugin builds prepare Hermes automatically when engine is omitted or set to "static-hermes". Run the command above to prewarm the toolchain or prepare it explicitly before a build. Toolchain versions are pinned in toolchain-versions.json; the files follow the upstream release pin schema, upstream Git pin schema, and toolchain versions schema. The package also carries the WASI 2 CMake toolchain adjustment required by Hermes. Optional paths and build settings are listed under Build flags.

Engine and runtime profiles ​

Omitting engine selects Static Hermes. Set "engine": "quickjs" in the package's pumpkinPlugin configuration to select QuickJS.

json
"pumpkinPlugin": {
  "entry": "src/plugin.ts",
  "output": "build/plugin.wasm",
  "wasi": [],
  "staticHermesRuntime": "full"
}

Static Hermes defaults to the lean profile. Both profiles execute precompiled Hermes bytecode; full also retains runtime source compilation, including eval and the Function constructor. Set staticHermesRuntime to "full" to use it. This setting requires the Static Hermes engine and cannot be combined with QuickJS.

Build the plugin with:

sh
pnpm --filter <plugin-package-name> build

Static Hermes builds prepare the toolchain automatically when required.

Production and development builds ​

Production builds minify the JavaScript bundle, compile it to optimized Hermes bytecode with function names and debug information stripped, and compile the native WASI code with -Oz. Function/data sections allow unused code to be removed at link time. The linker strips symbols from the production component. Each production component must be no larger than 5 MiB (5,242,880 bytes).

Development builds keep the JavaScript bundle readable and retain Hermes source locations and native line tables for backtraces. Native code remains size optimized. The specific compiler and linker flags are listed below.

Build flags ​

These settings cover the build tools and paths, Hermes library configuration, Hermes bytecode compilation, and WASI C/C++ compilation and linking.

JavaScript-to-C compiler ​

Production runs hermesc -color -O4 -fstrip-function-names -g0 -emit-binary:

FlagEffect
-colorPrints colored compiler diagnostics in build logs. The build always passes this flag, including development builds.
-OgApplies Hermes optimizations intended to remain suitable for debugging; used in development.
-O4Optimizes Hermes bytecode.
-fstrip-function-namesRemoves function names from the generated string table.
-g0Omits compiler debug information.
-g1Keeps Hermes source locations for JavaScript backtraces without per-instruction debug data.
-emit-binaryEmits Hermes bytecode embedded in the component.

Development uses hermesc -Og -g1 -emit-binary: the bundle stays non-minified, function names remain, and Hermes keeps source locations for JavaScript backtraces. Native C/C++ compilation uses -Oz -gline-tables-only -DNDEBUG -ffunction-sections -fdata-sections; this keeps native line tables and function names while minimizing code and allowing unused sections to be removed. Development components retain those line tables; the linker does not use --strip-debug or --strip-all.

FlagEffect
-OzOptimizes native WebAssembly for minimum size.
-gline-tables-onlyKeeps native source-line mappings for backtraces without full variable/type debug data.
-DNDEBUGRemoves C/C++ assertions.
-ffunction-sections -fdata-sectionsSeparates code and data so unused sections can be removed.
-DSTATIC_HERMESSelects the Static Hermes implementation in the native JSI shim.
-mllvm -wasm-enable-sjlj with -lsetjmpProvides the setjmp/longjmp lowering Hermes uses for JavaScript exceptions.
-D_WASI_EMULATED_MMAN, -D_WASI_EMULATED_PROCESS_CLOCKSEnables wasi-libc emulation for the POSIX calls Hermes needs.
-lwasi-emulated-mman, -lwasi-emulated-process-clocksLinks those wasi-libc emulation implementations.
-fwasm-exceptionsKeeps C++ exceptions for error handling in the JSI shim.

-mexec-model=reactorBuilds a reactor module whose plugin lifecycle is controlled by the component host.

API and platform coverage ​

Pumpkin API ​

@pumpkin-plugins/build supplies the pinned WIT directory and owns the Pumpkin API version and WASI definitions. Each build generates the component ABI and the ignored generated/api-enums.generated.h. It also generates event payload converters only for the WIT variants and fields used by the bundled plugin.

The native JSI shim implements part of the Pumpkin API: plugin lifecycle and metadata, command and task dispatch, event registration and dispatch, selected server/player/world methods, logging, scheduling, and Java custom payloads. Calls outside that supported subset are not available through Static Hermes.

The generated Pumpkin API facades reject host calls during on_unload, except scheduler.cancel-task, which plugins need to stop scheduled callbacks. Cancel scheduled tasks and perform local cleanup during unload; other host calls remain unavailable. This guard prevents calls from re-entering the WASM store during shutdown.

WASI ​

Static Hermes reads the WIT directory prepared by @pumpkin-plugins/build. It validates every operation in an imported WASI interface, including operations the plugin does not use, and emits native adapters only for operations used by the bundle. The current imported WASI 0.2.3 surface covers filesystem, HTTP, streams, clocks, TCP, UDP, and sockets. The build enables a feature-gated WIT operation when the bundle uses it.

Static Hermes development builds bypass the shared automatic Market update check. WASI 3 support is deferred.

See the tool guide and API reference on the documentation site.
