BigInt QuickJS runtime ​

quickjs-runtime-bigint.wasm is built from the pinned upstream componentize-qjs source with componentize-qjs-bigint.patch applied. The patch converts WIT u64 and s64 values to JavaScript bigint on push and reads them from JavaScript bigint on pop. The runtime is Apache-2.0; its license is included as LICENSE.componentize-qjs.

The runtime tracks imported resource ownership, provides drop() and Symbol.dispose, and releases unreachable owned handles after QuickJS evaluation. Without those releases, handles can exhaust the component resource table even when plugins request disposal. Event resources returned to Pumpkin must remain alive until the return transfers ownership to the host.

The build tool passes this runtime to its componentizer through --runtime. That option cannot be combined with the componentizer's --opt-size mode, so the runtime itself is compiled with the size optimization flags listed in its generated provenance below.

Rebuild ​

Use the Node.js range and toolchain values shown above. Install the listed Rust target and put the pinned Rust toolchain first on PATH.

sh
git clone https://github.com/andreiltd/componentize-qjs.git /tmp/componentize-qjs
git -C /tmp/componentize-qjs checkout --detach e563c6d6ae50b087980414015663ca9c948c09bb
sh
QJS_SOURCE_DIR=/tmp/componentize-qjs \
WASI_SDK_PATH=/path/to/wasi-sdk \
CARGO_TARGET_DIR=/tmp/componentize-qjs-target \
RUNTIME_OUTPUT_DIR=/tmp/componentize-qjs-candidate \
  ./tools/build/runtime/build.sh

The script accepts a clean pinned checkout or exactly the declared patch, rejects other tracked, untracked and ignored inputs, checks the dependency lock and tool versions, and builds with cargo --locked. It emits a candidate runtime and a provenance.json manifest in RUNTIME_OUTPUT_DIR (default: $CARGO_TARGET_DIR/runtime-artifact). It does not replace the vendored runtime. A failure before publication leaves a previous candidate untouched. Each candidate manifest records the artifact hash, operating system and architecture, and OS release.

sh
node tools/build/runtime/provenance.mjs verify-candidate /tmp/componentize-qjs-candidate
node tools/build/runtime/provenance.mjs verify tools/build/runtime

The build script checks source and build inputs against the checked-in manifest before building. verify-candidate checks the candidate manifest against the pinned values and the artifact against its recorded hash. verify checks the shipped artifact against the pinned hash. Neither command independently rebuilds source.

CI compares two isolated builds on the same runner and loads the candidate in real Pumpkin integration tests before permitting a code release. This checks same-runner repeatability and runtime behavior; it does not guarantee matching bytes across build environments.

Future runtime updates must review the source patch/license, refresh the manifest and repeat clean builds plus bundle and real-server checks. Replacing the shipped binary is a separate reviewed step.
